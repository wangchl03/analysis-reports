01

券的作用是「时间加速」，不是「行为区分」。

券把优质用户提前集中到第一周（实验组第一周回归者历史逾期 0.23，低于基线 0.28），而不是改变用户的犹豫行为。

02

剩余池浓缩效应。

优质用户被提前抽走后，实验组剩余池中高息（高风险定价）用户占比被动上升——第二周回归者高息率 0.351 vs 基线 0.304。

03

对照组无加速器，优质用户自然释放。

对照组第二周回归者高息率 0.220（全场最低），仍是好用户，因此其质量恶化被推迟到第三周。

04

完整机制闭环。

实验组质量曲线「好→差→差」与对照组「好→好→差」形状相同，只是实验组整体前移一个窗口——与盈利率观察完全吻合。

05

补充画像：实验组晚回归者是「高频高息」风险用户。

历史借款次数显示：第一周两组一致（2.93 次）；券过期后对照组回落到基线（2.57~2.77，低频慢热型），实验组不降反升（3.41/3.45 次，高频）。结合高息率（实验组晚回归 0.33~0.35 vs 对照组 0.22~0.24），实验组晚回归用户 = 借款次数多但风险定价高的用户——降息券对高频借款用户吸引力大，优质高频用户第一周被拉走，剩下的高频高息用户因借款惯性持续回归，拖累后续窗口盈利。

四、核心结论汇总

01

券的拉动只存在第一周（券有效期内）。

第一周提单率实验组 32.73% vs 对照组 25.27%（+7.46pp）；第二周 +1.30pp、第三周 +1.45pp、21 天后 +2.94pp。券过期后两组待遇一致，转化差异大幅收窄。

02

第二周是质量分水岭：实验组先转亏。

第二周对照组盈利率仍 +16.92%（赚 4.8 万），实验组转负 -11.08%（亏 2.2 万），实验组逾期率 40.54% 反超对照组的 28.75%。

03

券的长期副作用：优质用户被前置消化。

券把「会回来」的优质用户集中在第一周转化（第一周实验组逾期率反而更低：25.65% vs 30.28%），导致实验组后续窗口的回归用户质量系统性变差——第二周起实验组的逾期率、盈利率全面差于对照组。

04

量利权衡净结果为负：放款额 +11.3%，盈利额 -62.6%。

实验组放款 175 万 vs 对照组 157 万；但盈利额 2.4 万 vs 6.5 万。30% 降息削薄利差（盈利率 2.59% vs 7.92%），规模增量不足以弥补。

五、策略建议

A

资源聚焦第一周（券有效期），做足触达。

第一周是唯一量质双优窗口（盈利率 19.60%），把召回触达、再营销、客服跟进全部压在第一周内完成，最大化券期转化。

B

对第三周及以后回归用户升级风控。

逾期率 44%+、盈利率 -10%~-46%，建议对召回日+14 天后首次提单的用户加审、压降额度或直接拒绝。

C

重新测算降息券档位，寻找量利平衡点。

30% 降息使整体盈利率下降 5.33pp（7.92%→2.59%）。建议 AB 测试 10%/20% 档，以「第一周提单率增量 × 盈利率」最大化盈利额。

模块一：构建 7 月召回实验用户（4 批 T4 合并，含召回日）
-- ============================================================

-- 召回日 = 表名最后一个日期（如 0716_0721 -> 2026-07-21）

WITH t7 AS (
    SELECT user_id, ab_group, MIN(recall_date) AS recall_date
    FROM (
        SELECT churn_user_id::bigint AS user_id, ab_group,
               DATE '2026-07-21' AS recall_date
        FROM wangchuanliang.no_apply_0716_0721_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-22'
        FROM wangchuanliang.no_apply_0717_0722_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-23'
        FROM wangchuanliang.no_apply_0718_0723_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-24'
        FROM wangchuanliang.no_apply_0719_0724_30pct
    ) x
    GROUP BY user_id, ab_group
)
SELECT ab_group, COUNT(DISTINCT user_id) AS 用户数
FROM t7
GROUP BY ab_group
ORDER BY ab_group;
模块二：总和统计（整体漏斗 + 逾期率 + 盈利率）
-- 口径：盈利率 = (repaid_amt - remit_amt) / remit_amt
--       仅计 is_remit=1 且 loan_status_code <> 5（排除在途）的订单
--       逾期率 = status=8 / status in (7,8)（排除在途）
WITH t7 AS (
    SELECT user_id, ab_group, MIN(recall_date) AS recall_date
    FROM (
        SELECT churn_user_id::bigint AS user_id, ab_group, DATE '2026-07-21' AS recall_date
        FROM wangchuanliang.no_apply_0716_0721_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-22'
        FROM wangchuanliang.no_apply_0717_0722_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-23'
        FROM wangchuanliang.no_apply_0718_0723_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-24'
        FROM wangchuanliang.no_apply_0719_0724_30pct
    ) x
    GROUP BY user_id, ab_group
)
SELECT
    COUNT(DISTINCT t7.user_id)                                              AS 用户数,
    COUNT(DISTINCT CASE WHEN o.serial_id IS NOT NULL THEN t7.user_id END)   AS 提单用户,
    ROUND(COUNT(DISTINCT CASE WHEN o.serial_id IS NOT NULL THEN t7.user_id END) * 100.0
          / NULLIF(COUNT(DISTINCT t7.user_id), 0), 2)                       AS 提单率,
    COUNT(o.serial_id)                                                      AS 订单数,
    COUNT(CASE WHEN o.is_remit = 1 THEN 1 END)                              AS 放款订单,
    ROUND(SUM(CASE WHEN o.is_remit = 1 THEN o.remit_amt ELSE 0 END)::numeric, 2) AS 放款金额,
    COUNT(CASE WHEN o.is_remit = 1 AND o.loan_status_code = 8 THEN 1 END)   AS 逾期订单,
    COUNT(CASE WHEN o.is_remit = 1 AND o.loan_status_code IN (7,8) THEN 1 END) AS 到期订单,
    ROUND(COUNT(CASE WHEN o.is_remit = 1 AND o.loan_status_code = 8 THEN 1 END) * 100.0
          / NULLIF(COUNT(CASE WHEN o.is_remit = 1 AND o.loan_status_code IN (7,8) THEN 1 END), 0), 2) AS 逾期率,
    ROUND((SUM(CASE WHEN o.is_remit = 1 AND o.loan_status_code <> 5 THEN o.repaid_amt ELSE 0 END)
         - SUM(CASE WHEN o.is_remit = 1 AND o.loan_status_code <> 5 THEN o.remit_amt ELSE 0 END))::numeric, 2) AS 盈利额,
    ROUND((SUM(CASE WHEN o.is_remit = 1 AND o.loan_status_code <> 5 THEN o.repaid_amt ELSE 0 END)
         - SUM(CASE WHEN o.is_remit = 1 AND o.loan_status_code <> 5 THEN o.remit_amt ELSE 0 END)) * 100.0
         / NULLIF(SUM(CASE WHEN o.is_remit = 1 AND o.loan_status_code <> 5 THEN o.remit_amt ELSE 0 END), 0), 2) AS 盈利率
FROM t7
LEFT JOIN wangchuanliang.order_loan_f_v2_copy o
       ON o.user_id = t7.user_id
      AND o.apply_date >= t7.recall_date;

         - SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN remit_amt ELSE 0 END))::numeric, 2) AS 盈利额,
    ROUND((SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN repaid_amt ELSE 0 END)
         - SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN remit_amt ELSE 0 END)) * 100.0
         / NULLIF(SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN remit_amt ELSE 0 END), 0), 2) AS 盈利率
FROM ords
GROUP BY win
ORDER BY CASE win WHEN '第一周' THEN 1 WHEN '第二周' THEN 2 WHEN '第三周' THEN 3 ELSE 4 END;

模块七：各窗口提单率（分母 = 各组实验用户总数）
-- 窗口提单率 = 窗口内提单用户 / 组内实验用户总数
WITH t7 AS (
    SELECT user_id, ab_group, MIN(recall_date) AS recall_date
    FROM (
        SELECT churn_user_id::bigint AS user_id, ab_group, DATE '2026-07-21' AS recall_date
        FROM wangchuanliang.no_apply_0716_0721_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-22'
        FROM wangchuanliang.no_apply_0717_0722_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-23'
        FROM wangchuanliang.no_apply_0718_0723_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-24'
        FROM wangchuanliang.no_apply_0719_0724_30pct
    ) x
    GROUP BY user_id, ab_group
)
SELECT
    t7.ab_group                                                             AS 分组,
    COUNT(DISTINCT t7.user_id)                                              AS 用户数,
    COUNT(DISTINCT CASE WHEN o.apply_date BETWEEN t7.recall_date AND t7.recall_date + 6
                         THEN t7.user_id END)                               AS 第一周提单用户,
    ROUND(COUNT(DISTINCT CASE WHEN o.apply_date BETWEEN t7.recall_date AND t7.recall_date + 6
                         THEN t7.user_id END) * 100.0
          / NULLIF(COUNT(DISTINCT t7.user_id), 0), 2)                       AS 第一周提单率,
    COUNT(DISTINCT CASE WHEN o.apply_date BETWEEN t7.recall_date + 7 AND t7.recall_date + 13
                         THEN t7.user_id END)                               AS 第二周提单用户,
    ROUND(COUNT(DISTINCT CASE WHEN o.apply_date BETWEEN t7.recall_date + 7 AND t7.recall_date + 13
                         THEN t7.user_id END) * 100.0
          / NULLIF(COUNT(DISTINCT t7.user_id), 0), 2)                       AS 第二周提单率,
    COUNT(DISTINCT CASE WHEN o.apply_date BETWEEN t7.recall_date + 14 AND t7.recall_date + 20
                         THEN t7.user_id END)                               AS 第三周提单用户,
    ROUND(COUNT(DISTINCT CASE WHEN o.apply_date BETWEEN t7.recall_date + 14 AND t7.recall_date + 20
                         THEN t7.user_id END) * 100.0
          / NULLIF(COUNT(DISTINCT t7.user_id), 0), 2)                       AS 第三周提单率,
    COUNT(DISTINCT CASE WHEN o.apply_date >= t7.recall_date + 21
                         THEN t7.user_id END)                               AS 21天后提单用户,
    ROUND(COUNT(DISTINCT CASE WHEN o.apply_date >= t7.recall_date + 21
                         THEN t7.user_id END) * 100.0
          / NULLIF(COUNT(DISTINCT t7.user_id), 0), 2)                       AS 21天后提单率
FROM t7
LEFT JOIN wangchuanliang.order_loan_f_v2_copy o
       ON o.user_id = t7.user_id
      AND o.apply_date >= t7.recall_date
GROUP BY t7.ab_group
ORDER BY t7.ab_group;
口径说明：召回日 = 各表名最后一个日期（07-21 / 07-22 / 07-23 / 07-24）；第一周 = 召回日至召回日+6（券有效期 7 天，仅实验组享 30% 降息券），第二周 = +7~+13，第三周 = +14~+20，21 天后 = +21 及之后。
盈利率 = (repaid_amt − remit_amt) / remit_amt，仅计 is_remit=1 且 loan_status_code ≠ 5（排除在途）的订单；逾期率 = status=8 / status∈(7,8)。21 天后窗口观测时长不一且到期样本少，其逾期率/盈利率仅供参考。
