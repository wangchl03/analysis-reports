一、统计口径与策略背景

01

统计口径。

策略触达用户后，用户7 天内主动获额、提单的数据。获额通过率用于评测对有效用户的触达效率（高获额通过率可减少用户投诉）。

02

8 月策略优化。

8 月份沿用 7 月召回策略，并对部分用户做了调整：①按「提单意愿分级」——对提单意愿等级最高的用户，给优惠力度较低的 10% 减息券；②按模型分——对高评分、活跃度低的用户，给优惠力度较高的 40% 减息券。

03

风控强化。

8 月剔除了较多风险用户，尤其对流失 90 天以上用户进行了严格筛选。

四、结论

01

获额通过率逐月提升，触达效率持续改善。

获额通过率 6月 94.5% → 7月 95.9% → 8月 97.6%，8 月环比提升 1.9pp。主要归因于 8 月剔除了较多风险用户、尤其对流失 90 天以上用户严格筛选，减少了无效/低质触达。

02

前 7 日提单率逐月提升，8 月环比 +5.7pp。

提单率 6月 36.0% → 7月 46.6% → 8月 52.3%。差异化减息券策略（高意愿用户给 10%、高评分低活跃用户给 40%）提升了转化效率。

03

8 月规模与效率双升。

8 月面向全量，获额用户 1,418、提单用户 724，规模约为 6 月的 3 倍、7 月的 1.6 倍，同时保持最高获额通过率和提单率——量质双优。

04

后续观测节点。

建议在召回后 14 日、21 日两个观测节点，进一步对比不同层级（提单意愿分级、模型分层）用户的获额提单数据，验证差异化券策略的持续性效果。

附录：完整 PGSQL

以下代码用于统计召回后前 7 天的获额、获额通过、提单数据（以 8 月为例，6/7 月替换数据源与召回日即可）。

模块一：召回后前 7 天获额提单漏斗
-- 口径：
--   获额用户 = 召回后前 7 天内 vir_date 有记录的用户
--   获额通过用户 = 其中 is_pass1 = 1
--   提单用户 = 获额通过用户中，获额记录 serial_id 关联到订单表
--   获额通过率 = 获额通过 / 获额；提单率 = 提单 / 获额通过
WITH t AS (
    SELECT DISTINCT churn_user_id::bigint AS user_id
    FROM wangchuanliang.t7recalllist_0818_0819
    WHERE recall_date = '2026-08-18'
)
SELECT
    v.vir_date                                                              AS 获额日期,
    COUNT(DISTINCT v.user_id)                                               AS 获额用户,
    COUNT(DISTINCT CASE WHEN v.is_pass1 = 1 THEN v.user_id END)             AS 获额通过用户,
    COUNT(DISTINCT CASE WHEN v.is_pass1 = 1 AND o.serial_id IS NOT NULL
                        THEN v.user_id END)                                 AS 提单用户,
    ROUND(COUNT(DISTINCT CASE WHEN v.is_pass1 = 1 THEN v.user_id END) * 100.0
          / NULLIF(COUNT(DISTINCT v.user_id), 0), 2)                        AS 获额通过率,
    ROUND(COUNT(DISTINCT CASE WHEN v.is_pass1 = 1 AND o.serial_id IS NOT NULL
                        THEN v.user_id END) * 100.0
          / NULLIF(COUNT(DISTINCT CASE WHEN v.is_pass1 = 1 THEN v.user_id END), 0), 2) AS 提单率
FROM t
JOIN wangchuanliang.order_vir_f_copy v ON v.user_id = t.user_id
LEFT JOIN wangchuanliang.order_loan_f_v2_copy o ON o.serial_id = v.serial_id
WHERE v.vir_date BETWEEN '2026-08-18' AND '2026-08-24'
GROUP BY v.vir_date
ORDER BY v.vir_date;
模块二：三组汇总对比（6月 / 7月 / 8月）
-- 6 月第一次测试：churned_user_4932，ab_group='treatment'，召回日 2026-06-12
-- 7 月第二次测试：user_test_verification_0708，ab_group='treatment'，召回日 2026-07-08
-- 8 月新策略：t7recalllist_0818_0819，recall_date='2026-08-18'（面向全量）
-- 各取召回后前 7 天汇总
-- 以 6 月为例：
WITH t AS (
    SELECT DISTINCT churn_user_id::bigint AS user_id
    FROM wangchuanliang.churned_user_4932
    WHERE ab_group = 'treatment'
)
SELECT
    COUNT(DISTINCT v.user_id)                                               AS 获额用户,
    COUNT(DISTINCT CASE WHEN v.is_pass1 = 1 THEN v.user_id END)             AS 获额通过用户,
    COUNT(DISTINCT CASE WHEN v.is_pass1 = 1 AND o.serial_id IS NOT NULL
                        THEN v.user_id END)                                 AS 提单用户,
    ROUND(COUNT(DISTINCT CASE WHEN v.is_pass1 = 1 THEN v.user_id END) * 100.0
          / NULLIF(COUNT(DISTINCT v.user_id), 0), 2)                        AS 获额通过率,
    ROUND(COUNT(DISTINCT CASE WHEN v.is_pass1 = 1 AND o.serial_id IS NOT NULL
                        THEN v.user_id END) * 100.0
          / NULLIF(COUNT(DISTINCT CASE WHEN v.is_pass1 = 1 THEN v.user_id END), 0), 2) AS 提单率
FROM t
JOIN wangchuanliang.order_vir_f_copy v ON v.user_id = t.user_id
LEFT JOIN wangchuanliang.order_loan_f_v2_copy o ON o.serial_id = v.serial_id
WHERE v.vir_date BETWEEN '2026-06-12' AND '2026-06-18';
口径说明：统计策略触达后用户 7 天内主动获额、提单的数据。获额通过率 = 获额通过用户/获额用户（评测对有效用户的触达效率）；提单率 = 提单用户/获额通过用户。三组实验：6月第一次测试（churned_user_4932）、7月第二次测试（user_test_verification_0708）、8月新策略面向全量（t7recalllist_0818_0819）。
