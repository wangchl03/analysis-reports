一、背景与口径

01

实验设计。

4 批 T5 流失用户（结清后 4 天未提单，共 1,317 人），召回日 07-21~07-24。对照组（无动作）657 人；实验组（30% 利息折扣券，有效期 7 天）660 人。

02

第一阶段（沉默期）。

结清日到召回日之间的 4 天（如 0716-0721 组：结清 07-16、召回 07-21，第一阶段 = 07-17/18/19/20），这 4 天用户未提单。第一阶段活跃 = 该 4 天在 event_track 有活跃记录。

03

分析对象。

第一周（召回日 ~ +6）提单用户及其订单。提单率 = 第一周提单用户 / 该分层总用户；盈利率统计第一周提单订单。

四、不活跃用户：降息券「用利率换还款率」的验证

两组不活跃用户提单率都是 19%，客群同质（随机分组），唯一差异是实验组订单享受降息。对比两组不活跃用户的第一周订单属性，验证降息的作用机制。

五、核心结论汇总

01

第一阶段活跃度是召回分层的第一变量。

它同时预测提单率（39.65% vs 19.30%，2 倍）和盈利率（+24.93% vs +1.52%，差 23.4pp），且比「召回后活跃」信号更前置——在召回触达前即可观测。

02

降息券的有效性由活跃度决定。

活跃用户：提单率 +14.12pp（券=拉新工具）；不活跃用户：提单率 +0.19pp（券无效），但逾期率 -14.7pp（券=风控工具）。同一张券，两类用户身上扮演两种角色。

03

四象限策略分化。

对照组活跃（质最优）：无需干预；实验组活跃（量最大）：券拉量但降息削利差，需测算券档位；实验组不活跃：券当风控工具用，微利可放；对照组不活跃：唯一亏损象限（-9.56%），无券时应收紧风控。

04

降息的「利率换还款率」机制成立。

对还款能力边缘的不活跃用户，30% 降息把逾期率从 41.82% 压到 27.12%，省下的坏账损失（本金）远大于让渡的利息（7.8pp），净盈利率 +20.7pp。

六、策略建议

A

召回触达资源向第一阶段活跃用户倾斜。

活跃用户转化率高 2 倍、质量好 23pp，是召回 ROI 最高的客群；不活跃用户优先用低成本触达（短信/推送），不配高价值券。

B

活跃用户发券要算「量利平衡点」。

券对活跃用户拉量 +14.12pp，但盈利率从 31.59% 降到 20.19%（-11.4pp）。建议测 10%/20% 档位，最大化「提单率增量 × 盈利率」。

C

不活跃用户把降息券当「风控工具」。

不活跃用户吃不到量，但降息显著降低其逾期率（-14.7pp）——若担心该客群坏账，可定向发小幅度降息券改善还款，而不是把它当拉新工具。

D

无券场景下对不活跃用户收紧风控。

对照组不活跃用户盈利率 -9.56%、逾期率 41.82%——若整体停发降息券，需同步对「第一阶段沉默」用户加审或压降额度，避免该象限亏损扩大。

附录：完整 PGSQL 代码

以下代码覆盖本报告全部统计。执行前请按实际需要调整统计截止日。

模块一：第一阶段活跃/不活跃 × 分组完整统计（含提单率）
-- 口径：
--   第一阶段 = 结清后到召回前的 4 天（召回日-4 ~ 召回日-1，不含结清日与召回日）
--   第一阶段活跃 = 该 4 天在 event_track 有活跃记录
--   第一周提单 = apply_date 在 [召回日, 召回日+6]
--   提单率 = 第一周提单用户 / 该分层总用户
--   盈利率 = (repaid_amt - remit_amt) / remit_amt，仅计 is_remit=1 且 status <> 5
WITH t7 AS (
    SELECT user_id, ab_group, MIN(recall_date) AS recall_date
    FROM (
        SELECT churn_user_id::bigint AS user_id, ab_group, DATE '2026-07-21' AS recall_date
        FROM wangchuanliang.no_apply_0716_0721_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-22'
        FROM wangchuanliang.no_apply_0717_0722_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-23'
        FROM wangchuanliang.no_apply_0718_0723_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-24'
        FROM wangchuanliang.no_apply_0719_0724_30pct
    ) x
    GROUP BY user_id, ab_group
),
p1_active AS (
    SELECT DISTINCT t7.user_id
    FROM t7
    JOIN wangchuanliang.event_track e
      ON e.user_id = t7.user_id
     AND e.active_date BETWEEN t7.recall_date - 4 AND t7.recall_date - 1
)
SELECT
    t7.ab_group                                                             AS 分组,
    CASE WHEN pa.user_id IS NOT NULL THEN '第一阶段活跃' ELSE '第一阶段不活跃' END AS 第一阶段,
    COUNT(DISTINCT t7.user_id)                                              AS 总用户,
    COUNT(DISTINCT CASE WHEN o.serial_id IS NOT NULL THEN t7.user_id END)   AS 提单用户,
    ROUND(COUNT(DISTINCT CASE WHEN o.serial_id IS NOT NULL THEN t7.user_id END) * 100.0
          / NULLIF(COUNT(DISTINCT t7.user_id), 0), 2)                       AS 提单率,
    COUNT(o.serial_id)                                                      AS 订单数,
    COUNT(CASE WHEN o.is_remit = 1 THEN 1 END)                              AS 放款订单,
    ROUND(SUM(CASE WHEN o.is_remit = 1 THEN o.remit_amt ELSE 0 END)::numeric, 2) AS 放款金额,
    ROUND(COUNT(CASE WHEN o.is_remit = 1 AND o.loan_status_code = 8 THEN 1 END) * 100.0
          / NULLIF(COUNT(CASE WHEN o.is_remit = 1 AND o.loan_status_code IN (7,8) THEN 1 END), 0), 2) AS 逾期率,
    ROUND((SUM(CASE WHEN o.is_remit = 1 AND o.loan_status_code <> 5 THEN o.repaid_amt ELSE 0 END)
         - SUM(CASE WHEN o.is_remit = 1 AND o.loan_status_code <> 5 THEN o.remit_amt ELSE 0 END))::numeric, 2) AS 盈利额,
    ROUND((SUM(CASE WHEN o.is_remit = 1 AND o.loan_status_code <> 5 THEN o.repaid_amt ELSE 0 END)
         - SUM(CASE WHEN o.is_remit = 1 AND o.loan_status_code <> 5 THEN o.remit_amt ELSE 0 END)) * 100.0
         / NULLIF(SUM(CASE WHEN o.is_remit = 1 AND o.loan_status_code <> 5 THEN o.remit_amt ELSE 0 END), 0), 2) AS 盈利率
FROM t7
LEFT JOIN p1_active pa ON pa.user_id = t7.user_id
LEFT JOIN wangchuanliang.order_loan_f_v2_copy o
       ON o.user_id = t7.user_id
      AND o.apply_date BETWEEN t7.recall_date AND t7.recall_date + 6
GROUP BY t7.ab_group, 2
ORDER BY t7.ab_group, 2;
模块二：不活跃用户第一周订单属性对比（降息换还款率验证）
-- 验证：两组不活跃用户提单率相同（客群同质），唯一差异是实验组订单享受降息
-- 对比费率、期数、件均、逾期率、盈利率
WITH t7 AS (
    SELECT user_id, ab_group, MIN(recall_date) AS recall_date
    FROM (
        SELECT churn_user_id::bigint AS user_id, ab_group, DATE '2026-07-21' AS recall_date
        FROM wangchuanliang.no_apply_0716_0721_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-22'
        FROM wangchuanliang.no_apply_0717_0722_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-23'
        FROM wangchuanliang.no_apply_0718_0723_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-24'
        FROM wangchuanliang.no_apply_0719_0724_30pct
    ) x
    GROUP BY user_id, ab_group
),
p1_inactive AS (
    SELECT DISTINCT t7.user_id
    FROM t7
    WHERE NOT EXISTS (
        SELECT 1 FROM wangchuanliang.event_track e
        WHERE e.user_id = t7.user_id
          AND e.active_date BETWEEN t7.recall_date - 4 AND t7.recall_date - 1
    )
)
SELECT
    t7.ab_group                                                             AS 分组,
    COUNT(DISTINCT o.serial_id)                                             AS 订单数,
    ROUND(AVG(o.total_term)::numeric, 2)                                    AS 平均期数,
    ROUND(SUM(o.pre_amt + o.post_amt) * 100.0
          / NULLIF(SUM(o.remit_amt), 0), 2)                                 AS 费率,
    ROUND(AVG(o.remit_amt)::numeric, 0)                                     AS 件均放款,
    ROUND(COUNT(CASE WHEN o.loan_status_code = 8 THEN 1 END) * 100.0
          / NULLIF(COUNT(CASE WHEN o.loan_status_code IN (7,8) THEN 1 END), 0), 2) AS 逾期率,
    ROUND((SUM(CASE WHEN o.loan_status_code <> 5 THEN o.repaid_amt ELSE 0 END)
         - SUM(CASE WHEN o.loan_status_code <> 5 THEN o.remit_amt ELSE 0 END)) * 100.0
         / NULLIF(SUM(CASE WHEN o.loan_status_code <> 5 THEN o.remit_amt ELSE 0 END), 0), 2) AS 盈利率
FROM t7
JOIN p1_inactive pi ON pi.user_id = t7.user_id
JOIN wangchuanliang.order_loan_f_v2_copy o
  ON o.user_id = t7.user_id
 AND o.apply_date BETWEEN t7.recall_date AND t7.recall_date + 6
 AND o.is_remit = 1
GROUP BY t7.ab_group
ORDER BY t7.ab_group;
口径说明：第一阶段 = 结清后到召回前的 4 天（召回日-4 ~ 召回日-1）；活跃 = 该 4 天 event_track 有记录；第一周 = 召回日 ~ +6。
盈利率 = (repaid_amt − remit_amt) / remit_amt，仅计 is_remit=1 且 loan_status_code ≠ 5；逾期率 = status=8 / status∈(7,8)。对照组无动作，实验组发 30% 利息折扣券（7 天有效）。不活跃用户样本较小（65/68 人），其逾期率/盈利率差异方向合理但需更大样本复核。
