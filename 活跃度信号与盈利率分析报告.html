一、研究背景与口径

01

研究问题。

流失用户召回场景中，降息券（treatment）对提单率和盈利率的影响；以及「上一周是否活跃」作为下一周提单订单盈利预测信号的有效性，是否在跨数据集、跨人群中稳定成立。

02

三组召回实验。

① no_apply（7/21~7/24 召回，T4 用户，30% 降息券，控制 657/实验 660）；② user_test_verification_0708（7/8 召回，控制 5327/实验 4250，分组不平衡）；③ churned_user_4932（6/12 召回，控制 1479/实验 3453，激励几乎无效）。

03

全量普通用户。

2026-01-01 起的全部放款订单（48 万笔），按「提单前 7 日是否有活跃记录」分组，并拆分首贷/复贷。

04

核心口径。

窗口 = 相对召回日的周分段（第一周=召回日~+6）；盈利率=(已还-放款本金)/放款本金，仅计 is_remit=1 且 status≠5；逾期率=status 8 / status∈(7,8)；活跃 = event_track 存在记录。

六、信号为什么反转：流失唤醒 vs 自然活跃

01

人群基线不同，「活跃」的含义相反。

召回实验的用户全部是流失用户（低活跃基线）：「W1 活跃」= 被召回成功唤醒 = 还款意愿在线 = 好信号；「W1 不活跃」= 连召回（甚至降息券）都唤不醒、第二周却突然来借 = 极端低意愿边缘用户（no_apply 实验组逾期率 83%、盈利率 -64%）。

02

全量自然池里「活跃」混入高频借款信号。

自然活跃的复贷用户中混入大量「周转型/借款成瘾型」高风险用户（活跃正是因为总在借，逾期率 33.39% 反而更高）；而「前 7 日不活跃才来借」的复贷用户是有真实需求才打开 App 的需求驱动型，还款更靠谱（+15.33%）。

03

规律的条件性成立。

活跃信号方向依赖人群基线：流失池（低活跃基线）中活跃 = 正向信号，强度随激励强度放大；自然池（高活跃基线）中活跃 = 中性偏负。这是典型的「效应修饰」——同一变量在不同人群中方向反转。

04

业务含义。

用「上周活跃」做风控/运营分层前，必须先判断用户处于「流失唤醒」还是「自然活跃」状态；更本质的风险变量是借款频率/周转强度，而不是活跃本身。

七、策略建议

A

召回资源聚焦第一周（券有效期）。

第一周是唯一量质双优窗口（盈利率 19.60%），把触达、再营销、客服跟进全部压在第一周内完成。

B

降息券只对优质用户精准发放。

券的核心价值是「提前锁定优质用户」而非多转化；全量发放会把高频高息风险用户也加速拉回，导致后续窗口亏损（第二周实验组 -11.08%）。

C

对晚回归用户升级风控。

第三周及以后回归的用户逾期率 44%+、盈利率 -10%~-46%；对召回日+14 天后首次提单的用户加审、压降额度或拒绝。重点拦截「召回触达但第一周零活跃」的实验组用户（逾期率 83%）。

D

活跃信号分场景使用。

流失召回场景：上周活跃 = 正向质量信号（优先触达、可给更优券）；自然场景：不要用活跃做风控分层（复贷内部信号反转），改用借款频率/周转强度变量。

附录：完整 PGSQL 代码

以下代码覆盖本报告全部统计：no_apply 四周窗口、机制验证、跨数据集验证、活跃信号与全量分析。执行前请按实际需要调整统计截止日。

模块一：no_apply 实验用户构建 + 四周窗口交叉统计
-- 数据源：no_apply_0716_0721_30pct / 0717_0722 / 0718_0723 / 0719_0724
-- 召回日 = 表名最后一个日期；第一周=召回日~+6（券期），第二周=+7~+13，第三周=+14~+20，21天后=+21起
WITH t7 AS (
    SELECT user_id, ab_group, MIN(recall_date) AS recall_date
    FROM (
        SELECT churn_user_id::bigint AS user_id, ab_group, DATE '2026-07-21' AS recall_date
        FROM wangchuanliang.no_apply_0716_0721_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-22'
        FROM wangchuanliang.no_apply_0717_0722_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-23'
        FROM wangchuanliang.no_apply_0718_0723_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-24'
        FROM wangchuanliang.no_apply_0719_0724_30pct
    ) x
    GROUP BY user_id, ab_group
),
ords AS (
    SELECT t7.ab_group, t7.user_id,
           CASE WHEN o.apply_date BETWEEN t7.recall_date AND t7.recall_date + 6
                THEN '第一周'
                WHEN o.apply_date BETWEEN t7.recall_date + 7 AND t7.recall_date + 13
                THEN '第二周'
                WHEN o.apply_date BETWEEN t7.recall_date + 14 AND t7.recall_date + 20
                THEN '第三周'
                ELSE '21天后' END                                             AS win,
           o.serial_id, o.is_remit, o.loan_status_code, o.remit_amt, o.repaid_amt
    FROM t7
    JOIN wangchuanliang.order_loan_f_v2_copy o
      ON o.user_id = t7.user_id
     AND o.apply_date >= t7.recall_date
)
SELECT
    ab_group                                                                AS 分组,
    win                                                                     AS 窗口,
    COUNT(DISTINCT user_id)                                                 AS 提单用户,
    COUNT(serial_id)                                                        AS 订单数,
    COUNT(CASE WHEN is_remit = 1 THEN 1 END)                                AS 放款订单,
    ROUND(SUM(CASE WHEN is_remit = 1 THEN remit_amt ELSE 0 END)::numeric, 2) AS 放款金额,
    ROUND(COUNT(CASE WHEN is_remit = 1 AND loan_status_code = 8 THEN 1 END) * 100.0
          / NULLIF(COUNT(CASE WHEN is_remit = 1 AND loan_status_code IN (7,8) THEN 1 END), 0), 2) AS 逾期率,
    ROUND((SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN repaid_amt ELSE 0 END)
         - SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN remit_amt ELSE 0 END))::numeric, 2) AS 盈利额,
    ROUND((SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN repaid_amt ELSE 0 END)
         - SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN remit_amt ELSE 0 END)) * 100.0
         / NULLIF(SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN remit_amt ELSE 0 END), 0), 2) AS 盈利率
FROM ords
GROUP BY ab_group, win
ORDER BY CASE win WHEN '第一周' THEN 1 WHEN '第二周' THEN 2 WHEN '第三周' THEN 3 ELSE 4 END, ab_group;
模块二：机制验证——历史特征（高息率/借款次数）按首次提单窗口
-- 验证「优质用户前置消化」：对照组 W2 回归者高息率应低于基线，实验组应高于基线
WITH feat AS (
    SELECT churn_user_id::bigint AS user_id, ab_group, DATE '2026-07-21' AS recall_date,
           total_remit_rnb, high_interest_rate, overdue_cnt
    FROM wangchuanliang.no_apply_0716_0721_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, DATE '2026-07-22', total_remit_rnb, high_interest_rate, overdue_cnt
    FROM wangchuanliang.no_apply_0717_0722_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, DATE '2026-07-23', total_remit_rnb, high_interest_rate, overdue_cnt
    FROM wangchuanliang.no_apply_0718_0723_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, DATE '2026-07-24', total_remit_rnb, high_interest_rate, overdue_cnt
    FROM wangchuanliang.no_apply_0719_0724_30pct
),
first_apply AS (
    SELECT f.user_id, f.ab_group, f.recall_date, MIN(o.apply_date) AS first_apply_date
    FROM feat f
    JOIN wangchuanliang.order_loan_f_v2_copy o
      ON o.user_id = f.user_id AND o.apply_date >= f.recall_date
    GROUP BY f.user_id, f.ab_group, f.recall_date
),
seg AS (
    SELECT user_id, ab_group, recall_date,
           CASE WHEN first_apply_date BETWEEN recall_date AND recall_date + 6 THEN 'W1'
                WHEN first_apply_date BETWEEN recall_date + 7 AND recall_date + 13 THEN 'W2'
                WHEN first_apply_date BETWEEN recall_date + 14 AND recall_date + 20 THEN 'W3'
                ELSE 'W4' END AS first_win
    FROM first_apply
)
SELECT
    s.first_win                                                             AS 首次提单窗口,
    f.ab_group                                                              AS 分组,
    COUNT(*)                                                                AS 人数,
    ROUND(AVG(f.high_interest_rate)::numeric, 3)                            AS 历史高息率,
    ROUND(AVG(f.overdue_cnt)::numeric, 2)                                   AS 历史逾期订单数,
    ROUND(AVG(f.total_remit_rnb)::numeric, 2)                               AS 历史借款次数
FROM seg s
JOIN feat f ON f.user_id = s.user_id AND f.ab_group = s.ab_group AND f.recall_date = s.recall_date
GROUP BY s.first_win, f.ab_group
ORDER BY s.first_win, f.ab_group;
模块三：第二周订单拆分——W1也提单（复贷） vs W2新提单
-- 口径：W2新提单 = 第二周有提单订单、且第一周没有提单订单的用户
WITH t7 AS (
    SELECT user_id, ab_group, MIN(recall_date) AS recall_date

模块五：0708 / 4932 五窗口统计（第一~四周 + 28天后）
-- 0708 实验：召回日 = 2026-07-08；4932 实验：召回日 = 2026-06-12
-- 第一周=+0~+6；第二周=+7~+13；第三周=+14~+20；第四周=+21~+27；28天后=+28 起
WITH t AS (
    SELECT DISTINCT churn_user_id::bigint AS user_id, ab_group
    FROM wangchuanliang.user_test_verification_0708          -- 换成 churned_user_4932 及对应召回日即可
),
ords AS (
    SELECT t.ab_group, t.user_id,
           CASE WHEN o.apply_date BETWEEN DATE '2026-07-08' AND DATE '2026-07-08' + 6 THEN '第一周'
                WHEN o.apply_date BETWEEN DATE '2026-07-08' + 7 AND DATE '2026-07-08' + 13 THEN '第二周'
                WHEN o.apply_date BETWEEN DATE '2026-07-08' + 14 AND DATE '2026-07-08' + 20 THEN '第三周'
                WHEN o.apply_date BETWEEN DATE '2026-07-08' + 21 AND DATE '2026-07-08' + 27 THEN '第四周'
                ELSE '28天后' END AS win,
           o.serial_id, o.is_remit, o.loan_status_code, o.remit_amt, o.repaid_amt
    FROM t
    JOIN wangchuanliang.order_loan_f_v2_copy o
      ON o.user_id = t.user_id AND o.apply_date >= DATE '2026-07-08'
)
SELECT
    ab_group                                                                AS 分组,
    win                                                                     AS 窗口,
    COUNT(DISTINCT user_id)                                                 AS 提单用户,
    COUNT(serial_id)                                                        AS 订单数,
    ROUND(COUNT(CASE WHEN is_remit = 1 AND loan_status_code = 8 THEN 1 END) * 100.0
          / NULLIF(COUNT(CASE WHEN is_remit = 1 AND loan_status_code IN (7,8) THEN 1 END), 0), 2) AS 逾期率,
    ROUND((SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN repaid_amt ELSE 0 END)
         - SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN remit_amt ELSE 0 END))::numeric, 2) AS 盈利额,
    ROUND((SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN repaid_amt ELSE 0 END)
         - SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN remit_amt ELSE 0 END)) * 100.0
         / NULLIF(SUM(CASE WHEN is_remit = 1 AND loan_status_code <> 5 THEN remit_amt ELSE 0 END), 0), 2) AS 盈利率
FROM ords
GROUP BY ab_group, win
ORDER BY ab_group,
         CASE win WHEN '第一周' THEN 1 WHEN '第二周' THEN 2 WHEN '第三周' THEN 3 WHEN '第四周' THEN 4 ELSE 5 END;
模块六：全量普通用户——提单前 7 日活跃 vs 不活跃（含首贷/复贷拆分）
-- 口径：前 7 日活跃 = 提单日往前 7 天（不含提单日）在 event_track 有活跃记录
-- 注意：event_track 无索引，用「先裁剪去重、再一次性 hash join」避免逐单 EXISTS 超时
WITH et AS (
    SELECT DISTINCT user_id, active_date
    FROM wangchuanliang.event_track
    WHERE active_date >= '2025-12-25'        -- 提前 7 天裁剪，减少扫描量
),
o AS (
    SELECT serial_id, user_id, apply_date, is_remit, loan_status_code,
           remit_amt, repaid_amt, loan_type
    FROM wangchuanliang.order_loan_f_v2_copy
    WHERE apply_date >= '2026-01-01'
      AND is_remit = 1
),
act AS (
    SELECT DISTINCT o.serial_id
    FROM o
    JOIN et ON et.user_id = o.user_id
     AND et.active_date >= o.apply_date - 7
     AND et.active_date < o.apply_date
)
-- 总体
SELECT
    CASE WHEN a.serial_id IS NOT NULL THEN '前7日活跃' ELSE '前7日不活跃' END AS 类型,
    COUNT(*)                                                                AS 订单数,
    COUNT(DISTINCT o.user_id)                                               AS 用户数,
    ROUND(COUNT(CASE WHEN o.loan_status_code = 8 THEN 1 END) * 100.0
          / NULLIF(COUNT(CASE WHEN o.loan_status_code IN (7,8) THEN 1 END), 0), 2) AS 逾期率,
    ROUND((SUM(CASE WHEN o.loan_status_code <> 5 THEN o.repaid_amt ELSE 0 END)
         - SUM(CASE WHEN o.loan_status_code <> 5 THEN o.remit_amt ELSE 0 END)) * 100.0
         / NULLIF(SUM(CASE WHEN o.loan_status_code <> 5 THEN o.remit_amt ELSE 0 END), 0), 2) AS 盈利率
FROM o
LEFT JOIN act a ON a.serial_id = o.serial_id
GROUP BY 1
ORDER BY 1;

-- 按首贷/复贷拆分
SELECT
    o.loan_type,
    CASE WHEN a.serial_id IS NOT NULL THEN '前7日活跃' ELSE '前7日不活跃' END AS 类型,
    COUNT(*)                                                                AS 订单数,
    ROUND(COUNT(CASE WHEN o.loan_status_code = 8 THEN 1 END) * 100.0
          / NULLIF(COUNT(CASE WHEN o.loan_status_code IN (7,8) THEN 1 END), 0), 2) AS 逾期率,
    ROUND((SUM(CASE WHEN o.loan_status_code <> 5 THEN o.repaid_amt ELSE 0 END)
         - SUM(CASE WHEN o.loan_status_code <> 5 THEN o.remit_amt ELSE 0 END)) * 100.0
         / NULLIF(SUM(CASE WHEN o.loan_status_code <> 5 THEN o.remit_amt ELSE 0 END), 0), 2) AS 盈利率
FROM o
LEFT JOIN act a ON a.serial_id = o.serial_id
GROUP BY o.loan_type, 2
ORDER BY o.loan_type, 2;
口径说明：盈利率 = (repaid_amt − remit_amt) / remit_amt，仅计 is_remit=1 且 loan_status_code ≠ 5（排除在途）的订单；逾期率 = status=8 / status∈(7,8)。
活跃 = event_track 当日有记录。no_apply 召回日 07-21~07-24；0708 召回日 07-08；4932 召回日 06-12；全量分析口径为提单前 7 日（不含提单日）。小样本分段（<100 人）数值仅供参考。
