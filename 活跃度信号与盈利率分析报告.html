一、研究背景与口径

01

研究问题。

流失用户召回场景中，降息券（treatment）对提单率和盈利率的影响；以及「上一周是否活跃」作为下一周提单订单盈利预测信号的有效性，是否在跨数据集、跨人群中稳定成立。

02

三组召回实验。

① no_apply（7/21~7/24 召回，T5 用户，30% 降息券，控制 657/实验 660）；② user_test_verification_0708（7/8 召回，控制 5327/实验 4250，分组不平衡）；③ churned_user_4932（6/12 召回，控制 1479/实验 3453，激励几乎无效）。

03

全量普通用户。

2026-01-01 起的全部放款订单，按「提单前 7 日是否有活跃记录」分组，并拆分首贷/复贷。

04

本版核心口径（分期级 + 到期订单）。

① 只统计已到期订单：订单到期日 due_date < current_date，未到期订单不统计；② 分期级统计：以 repayment_plan_v2_copy 每期一行，仅计 loan_status_code_period ∈ (7,8)（排除在途 status=5）；③ 盈利率 = (Σrepaid_amt_period − Σremit_amt_period) / Σremit_amt_period；④ 三个逾期率：金额=逾期分期放款金额/总放款金额、分期=逾期分期数/到期分期数、订单=有逾期分期的订单数/到期订单数；⑤ 活跃 = event_track 当日有记录。

六、信号为什么反转：流失唤醒 vs 自然活跃

01

人群基线不同，「活跃」的含义相反。

召回实验的用户全部是流失用户（低活跃基线）：「W1 活跃」= 被召回成功唤醒 = 还款意愿在线 = 好信号；「W1 不活跃」= 连召回（甚至降息券）都唤不醒、第二周却突然来借 = 极端低意愿边缘用户（no_apply 实验组到期口径下逾期率_订单 88.89%）。

02

全量自然池里「活跃」混入高频借款信号。

自然活跃的复贷用户中混入大量「周转型/借款成瘾型」高风险用户（活跃正是因为总在借）；而「前 7 日不活跃才来借」的复贷用户是有真实需求才打开 App 的需求驱动型，还款更靠谱（+17.18% vs +13.97%）。

03

到期口径修正了旧口径的偏差。

旧口径把在途订单未还部分计入亏损，导致「实验组深亏」「0708 第四周转负」等结论被夸大；到期口径下实验组整体仅比对照组低 0.9pp，且逾期率更低——降息的真实代价远小于旧口径估计。

04

业务含义。

用「上周活跃」做风控/运营分层前，必须先判断用户处于「流失唤醒」还是「自然活跃」状态；更本质的风险变量是借款频率/周转强度，而不是活跃本身。同时盈利率评估必须限定在已到期订单上，否则会系统性低估盈利。

七、策略建议

A

召回资源聚焦第一周（券有效期），做足触达。

到期口径下第一周实验组「量增利微减」且逾期率更低（17.47% vs 20.71%），是唯一量质双优窗口。

B

降息券的价值重估：是「风控工具」而非纯成本。

到期口径下实验组盈利率仅低 0.9pp，且三个逾期率全面低于对照组（订单 27.87% vs 29.75%）——降息换还款率基本覆盖让利成本，可维持或小幅优化券档位。

C

重点拦截「召回触达但第一周零活跃」的实验组用户。

该类用户第二周提单订单逾期率_订单高达 88.89%、盈利率 -49.44%（到期口径），应加审、压降额度或拒绝。

D

盈利率评估统一采用「到期订单」口径。

未到期在途订单不应计入盈利率，否则会系统性低估盈利、误导「量利权衡为负」的结论；各报告指标口径需统一。

附录：完整 PGSQL 代码

以下代码覆盖本报告全部统计（到期订单 + 分期级口径）。执行前请按实际需要调整统计截止日。

模块一：no_apply 汇总 + 四周窗口（到期订单，分期级）
-- 口径：
--   只统计已到期订单：due_date < current_date（未到期订单不统计）
--   分期级：repayment_plan_v2_copy 每期一行，仅计 loan_status_code_period in (7,8)（排除在途5）
--   盈利率 = (sum(repaid_amt_period) - sum(remit_amt_period)) / sum(remit_amt_period)
--   逾期率_金额 = sum(status=8 的 remit_amt_period) / sum(remit_amt_period)
--   逾期率_分期 = count(status=8 分期行) / count(分期行)
--   逾期率_订单 = count(distinct status=8 serial_id) / count(distinct serial_id)
WITH t7 AS (
    SELECT user_id, ab_group, MIN(recall_date) AS recall_date
    FROM (
        SELECT churn_user_id::bigint AS user_id, ab_group, DATE '2026-07-21' AS recall_date
        FROM wangchuanliang.no_apply_0716_0721_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-22'
        FROM wangchuanliang.no_apply_0717_0722_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-23'
        FROM wangchuanliang.no_apply_0718_0723_30pct
        UNION ALL
        SELECT churn_user_id::bigint, ab_group, DATE '2026-07-24'
        FROM wangchuanliang.no_apply_0719_0724_30pct
    ) x
    GROUP BY user_id, ab_group
),
ords AS (
    SELECT t7.ab_group,
           CASE WHEN a.apply_date BETWEEN t7.recall_date AND t7.recall_date + 6
                THEN '第一周'
                WHEN a.apply_date BETWEEN t7.recall_date + 7 AND t7.recall_date + 13
                THEN '第二周'
                WHEN a.apply_date BETWEEN t7.recall_date + 14 AND t7.recall_date + 20
                THEN '第三周'
                ELSE '21天后' END                                             AS win,
           a.serial_id, a.user_id, a.loan_status_code_period,
           a.remit_amt_period, a.repaid_amt_period
    FROM t7
    JOIN wangchuanliang.repayment_plan_v2_copy a
      ON a.user_id = t7.user_id
     AND a.remit_date >= t7.recall_date
    WHERE a.is_remit = 1
      AND a.due_date < current_date
      AND a.loan_status_code_period IN (7, 8)
)
-- 汇总（去掉 win 即按分组汇总）
SELECT
    ab_group                                                                AS 分组,
    win                                                                     AS 窗口,
    COUNT(DISTINCT serial_id)                                               AS 到期件数,
    COUNT(DISTINCT user_id)                                                 AS 到期人数,
    ROUND(ROUND(SUM(repaid_amt_period) - SUM(remit_amt_period), 2)
          / NULLIF(ROUND(SUM(remit_amt_period), 2), 0) * 100, 2)            AS 盈利率,
    ROUND((SUM(CASE WHEN loan_status_code_period = 8 THEN remit_amt_period ELSE 0 END) + 0.0)
          / NULLIF(SUM(remit_amt_period), 0) * 100, 2)                      AS 逾期率_金额,
    ROUND((COUNT(CASE WHEN loan_status_code_period = 8 THEN serial_id END) + 0.0)
          / NULLIF(COUNT(serial_id), 0) * 100, 2)                           AS 逾期率_分期,
    ROUND((COUNT(DISTINCT CASE WHEN loan_status_code_period = 8 THEN serial_id END) + 0.0)
          / NULLIF(COUNT(DISTINCT serial_id), 0) * 100, 2)                  AS 逾期率_订单
FROM ords
GROUP BY ab_group, win
ORDER BY ab_group,
         CASE win WHEN '第一周' THEN 1 WHEN '第二周' THEN 2 WHEN '第三周' THEN 3 ELSE 4 END;
模块二：机制验证——历史特征（高息率/借款次数）按首次提单窗口
-- 口径不变（历史特征），保留原逻辑
WITH feat AS (
    SELECT churn_user_id::bigint AS user_id, ab_group, DATE '2026-07-21' AS recall_date,
           total_remit_rnb, high_interest_rate, overdue_cnt
    FROM wangchuanliang.no_apply_0716_0721_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, DATE '2026-07-22', total_remit_rnb, high_interest_rate, overdue_cnt
    FROM wangchuanliang.no_apply_0717_0722_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, DATE '2026-07-23', total_remit_rnb, high_interest_rate, overdue_cnt
    FROM wangchuanliang.no_apply_0718_0723_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, DATE '2026-07-24', total_remit_rnb, high_interest_rate, overdue_cnt
    FROM wangchuanliang.no_apply_0719_0724_30pct
),
first_apply AS (
    SELECT f.user_id, f.ab_group, f.recall_date, MIN(o.apply_date) AS first_apply_date
    FROM feat f
    JOIN wangchuanliang.order_loan_f_v2_copy o
      ON o.user_id = f.user_id AND o.apply_date >= f.recall_date
    GROUP BY f.user_id, f.ab_group, f.recall_date
),
seg AS (
    SELECT user_id, ab_group, recall_date,
           CASE WHEN first_apply_date BETWEEN recall_date AND recall_date + 6 THEN 'W1'
                WHEN first_apply_date BETWEEN recall_date + 7 AND recall_date + 13 THEN 'W2'
                WHEN first_apply_date BETWEEN recall_date + 14 AND recall_date + 20 THEN 'W3'
                ELSE 'W4' END AS first_win
    FROM first_apply

模块四：0708 / 4932 五窗口统计（到期订单口径）
-- 0708 召回日 = 2026-07-08；4932 召回日 = 2026-06-12
-- 第一周=+0~+6；第二周=+7~+13；第三周=+14~+20；第四周=+21~+27；28天后=+28 起
WITH t AS (
    SELECT DISTINCT churn_user_id::bigint AS user_id, ab_group
    FROM wangchuanliang.user_test_verification_0708        -- 换成 churned_user_4932 及对应召回日即可
),
ords AS (
    SELECT t.ab_group,
           CASE WHEN a.apply_date BETWEEN DATE '2026-07-08' AND DATE '2026-07-08' + 6 THEN '第一周'
                WHEN a.apply_date BETWEEN DATE '2026-07-08' + 7 AND DATE '2026-07-08' + 13 THEN '第二周'
                WHEN a.apply_date BETWEEN DATE '2026-07-08' + 14 AND DATE '2026-07-08' + 20 THEN '第三周'
                WHEN a.apply_date BETWEEN DATE '2026-07-08' + 21 AND DATE '2026-07-08' + 27 THEN '第四周'
                ELSE '28天后' END AS win,
           a.serial_id, a.user_id, a.loan_status_code_period,
           a.remit_amt_period, a.repaid_amt_period
    FROM t
    JOIN wangchuanliang.repayment_plan_v2_copy a
      ON a.user_id = t.user_id
     AND a.remit_date >= DATE '2026-07-08'
    WHERE a.is_remit = 1
      AND a.due_date < current_date
      AND a.loan_status_code_period IN (7, 8)

    win                                                                     AS 窗口,

    ROUND(ROUND(SUM(repaid_amt_period) - SUM(remit_amt_period), 2)
          / NULLIF(ROUND(SUM(remit_amt_period), 2), 0) * 100, 2)            AS 盈利率,

          / NULLIF(SUM(remit_amt_period), 0) * 100, 2)                      AS 逾期率_金额,
    ROUND((COUNT(DISTINCT CASE WHEN loan_status_code_period = 8 THEN serial_id END) + 0.0)
          / NULLIF(COUNT(DISTINCT serial_id), 0) * 100, 2)                  AS 逾期率_订单
FROM ords
GROUP BY ab_group, win
ORDER BY ab_group,
         CASE win WHEN '第一周' THEN 1 WHEN '第二周' THEN 2 WHEN '第三周' THEN 3 WHEN '第四周' THEN 4 ELSE 5 END;

模块六：全量普通用户——提单前 7 日活跃 vs 不活跃（到期口径）
-- 口径：前 7 日活跃 = 提单日往前 7 天（不含提单日）在 event_track 有活跃记录
-- 只统计已到期订单（due_date < current_date），分期级
-- event_track 无索引：先裁剪去重、再一次性 hash join，避免逐单 EXISTS 超时
WITH et AS (
    SELECT DISTINCT user_id, active_date
    FROM wangchuanliang.event_track
    WHERE active_date >= '2025-12-25'
),
o AS (
    SELECT serial_id, user_id, apply_date, loan_type
    FROM wangchuanliang.order_loan_f_v2_copy
    WHERE apply_date >= '2026-01-01'
      AND is_remit = 1
),
act AS (
    SELECT DISTINCT o.serial_id
    FROM o
    JOIN et ON et.user_id = o.user_id
     AND et.active_date >= o.apply_date - 7
     AND et.active_date < o.apply_date
)
-- 总体 + 按首贷/复贷拆分（换 GROUP BY 即可）
SELECT
    o.loan_type,
    CASE WHEN ac.serial_id IS NOT NULL THEN '前7日活跃' ELSE '前7日不活跃' END AS 类型,
    COUNT(DISTINCT a.serial_id)                                             AS 到期件数,
    ROUND(ROUND(SUM(a.repaid_amt_period) - SUM(a.remit_amt_period), 2)
          / NULLIF(ROUND(SUM(a.remit_amt_period), 2), 0) * 100, 2)          AS 盈利率,
    ROUND((SUM(CASE WHEN a.loan_status_code_period = 8 THEN a.remit_amt_period ELSE 0 END) + 0.0)
          / NULLIF(SUM(a.remit_amt_period), 0) * 100, 2)                    AS 逾期率_金额,
    ROUND((COUNT(DISTINCT CASE WHEN a.loan_status_code_period = 8 THEN a.serial_id END) + 0.0)
          / NULLIF(COUNT(DISTINCT a.serial_id), 0) * 100, 2)                AS 逾期率_订单
FROM o
JOIN wangchuanliang.repayment_plan_v2_copy a ON a.serial_id = o.serial_id
LEFT JOIN act ac ON ac.serial_id = o.serial_id
WHERE a.is_remit = 1
  AND a.due_date < current_date
  AND a.loan_status_code_period IN (7, 8)
GROUP BY o.loan_type, 2
ORDER BY o.loan_type, 2;
口径说明（本版）：只统计已到期订单（due_date < current_date，未到期订单不统计）；分期级统计（repayment_plan_v2_copy 每期一行，仅计 loan_status_code_period ∈ (7,8)，排除在途 status=5）。
盈利率 = (Σrepaid_amt_period − Σremit_amt_period) / Σremit_amt_period；逾期率_金额 = 逾期分期放款金额/总放款金额；逾期率_分期 = 逾期分期数/到期分期数；逾期率_订单 = 有逾期分期的订单数/到期订单数。
no_apply 召回日 07-21~07-24；0708 召回日 07-08；4932 召回日 06-12；全量口径为提单前 7 日（不含提单日）。第三周、21天后到期样本小（<32 件），数值仅供参考。
