一、循环贷产品核心规则

1.1 基础准入条件（Eligibility）

  • 用户资质仅针对系统评估的「优质用户」开放。
  • 前置触发点当前一笔在途订单的还款进度达到或超过 50% 时，用户获得开通循环贷的资格。

示例 B4 期产品结清第 2 期后2/4 = 50%

1.2 在途订单（Outstanding Orders）

  • 含义：用户处于还款阶段、尚未完全结清的贷款订单。
  • 状态判定：只要有一笔订单未结清，用户即处于「在途状态」；当所有订单全部结清，用户转为「非在途状态」。

1.3 循环贷判定逻辑（Cycle Logic）

  • 循环贷订单必须在「拥有在途订单」的前提下，再次申请并成功发放的贷款，才被定义为循环贷订单。
  • 非循环贷订单用户结清所有贷款（无在途订单）后，再次申请并获得的贷款，判定为普通订单（非循环贷）。

1.4 在途订单上限（Cap Limit）

  • 数量限制：同一用户最多只能同时拥有 两笔在途订单。
  • 动态控制：
    • 已有两笔在途时，系统自动冻结其循环贷开通资格。
    • 必须先完全结清其中一笔，使在途数降至 1 笔，且该笔订单还款进度 ≥ 50%，方可申请下一笔循环贷。

二、循环贷的商业价值与内在矛盾

价值（Benefits）

  • 避免用户流失：用户结清后处于非在途状态，再贷转化困难；循环贷在未结清时即放下一笔，直接把用户转化为下一笔贷款用户，提升转化率。
  • 筛选更多优质客户：贷款次数越多的用户资质越好，循环贷提高每次转化率，筛出更多能贷更多次的优质客户，带来更多利润。

弊端（Drawbacks）

  • 增加逾期率：上一笔还到一半即借下一笔，若上一笔随后停还即逾期，下一笔循环贷会连带逾期，额外增加一笔逾期订单。
  • 资质差的用户也转化：这类用户立刻逾期，产生「逾期两笔」，拉低盈利率。
最终目标：盈利额 = 放款金额 × 盈利率

循环贷通过牺牲盈利率（逾期率上升）来增加放款金额（转化率、订单量上升），最终看盈利额是否净增。这是一个「规模」与「效率」的矛盾状态。

三、核心风险因素：逾期两笔

3.1 机理

  • 开通循环贷后，用户拥有两笔在途订单。
  • 若第一笔订单逾期，第二笔循环贷也会连带逾期，产生「一个用户逾期两笔」的情况，损失最大。
  • 不给循环贷资格时，用户上一笔逾期后即失去贷款资格，只会逾期一笔。
  • 结论：每次贷款中「逾期两笔用户」的数量 / 占每次贷款总用户的占比，对盈利率有关键影响。

3.2 循环贷用户的定义

  • 在用户整个生命周期中，只要有一笔订单是循环贷订单，该用户即为「循环贷用户」。
  • 循环贷用户同时包含循环贷订单与非循环贷订单。
  • 首贷（第一笔贷款）都不是循环贷订单，最早从第二笔订单开始才可能出现循环贷订单。

3.3 资质与开通时序

  • 资质好的用户：第二笔订单即开通循环贷资格。
  • 资质一般的用户：可能第六笔订单才开通。
  • 资质差的用户：永远都不会开通循环贷资格。
  • 第二笔必须是在首贷结清前贷出才是循环贷；若首贷已结清再贷第二笔，则为非循环贷。

  • 订单 / 获额 / 循环贷类型：通过 serial_id 关联（三表均一对一）。

五、关键指标口径

5.1 获额额度逻辑

case
  when recycle_type = 2 or vir_date >= '2025-04-01'
       then coalesce(max_credit_apply_amt, max_risk_credit_amount)
  when recycle_type <> 2
       then coalesce(max_risk_credit_amount, max_credit_apply_amt)
  else 0
end
  • 2025-04-01 之后所有订单获额额度 = max_credit_apply_amt。
  • 2025-04-01 之前循环贷订单（recycle_type=2）获额额度 = max_credit_apply_amt；非循环贷订单获额额度 = max_risk_credit_amount。

5.2 额度使用率

额度使用率 = 提单金额（apply_amt） / 获额金额（获额额度）

漏斗关系：获额订单量 > 提单订单量 > 放款订单量（获额后不一定提单，提单后不一定放款）。可按放款月（remit_date）分组求不同月份的额度使用率。

5.3 订单状态语义

loan_status_code含义
5在途订单（未到期、未逾期）
7结清订单
8逾期订单
overdue_days含义
<= 0正常结清，未出现过逾期
> 0有过逾期经历（若已结清状态显示 7；若未结清状态显示 8，仍处逾期）

5.4 真逾期 / 假逾期用户

真逾期用户

存在订单状态为 8 的订单。

假逾期用户

不存在订单状态为 8 的订单，但存在 overdue_days > 0 的订单（即之前逾期过、后来结清，状态由 8 变 7），这些用户又具备提单资格。

六、红包（券）体系

6.1 三类红包

type名称说明
3降息券对利息减免，主要是 10% 息费减免，另有 5% / 20% / 30%
4提额券额度提升，如 5% / 10% / 20% 提额
2还款优惠券提前还款享受部分折扣

6.2 红包与订单的对应关系

  • coupon_no 唯一标识一个红包；coupon_amount 为红包金额。
  • 分期订单会产生多条记录（每期一条），同笔订单的 user_id、serial_id、coupon_no、create_time 相同，用 current_term 区分期数。
  • type=3 降息券：每笔订单只有一个红包（coupon_no 唯一）。
  • type=4 提额券：每笔订单只有一个红包（coupon_no 唯一）。
  • type=2 还款优惠券：一笔订单可有多个红包（coupon_no 不唯一）。
  • 一笔订单的红包金额 = 各期红包金额之和，即 sum(coupon_amount)。
  • 求「用降息券提单的订单」的筛选条件为 type = 3。

七、还款行为与逾期预测框架

7.1 分期订单单期逾期判定

repayment_plan_v2_copy.overdue_days_period > 0 代表该笔订单的某一期逾期了。

  • 例：一笔 4 期订单，前两期 overdue_days_period <= 0、后两期 > 0，说明用户前两期正常还款、后两期逾期。

7.2 多样化的还款行为

  • 有的用户提前结清。
  • 有的用户第一期正常还款，后面分期未还款而逾期。
  • 有的用户逾期后再结清。
  • 有的用户逾期后只还一部分、未结清，仍处逾期状态。

7.3 逾期预测的时点约束

  • 首贷 3 期产品，第 2 期结清即授予循环贷资格。
  • 因此要在第二期结清之前预测用户是否会逾期，可基于第一期还款特征。
  • 所有用户行为数据（含活跃数据）均须基于第二期结清之前的数据进行预测。

八、盈利分析注意事项

  • 用户出现假逾期后，其后所有放款订单的盈利率分析：不能过滤状态为 8 的订单，要过滤状态为 5 的订单。
  • 若用户假逾期回归后的第一笔放款订单状态是 8（即回归后立刻逾期），该笔订单盈利率很可能为负。
