活跃用户是「主战场」：券对高意向人群拉动最大。

实验组活跃用户提单率 26.42%（对照组 18.95%），+7.47pp；沉默用户仅 11.17%（对照 5.67%）。同一张券，投给主动回流的用户，转化增量几乎翻倍于沉默用户。

02

券的作用是「临门一脚」，不是「唤醒沉睡」。

对照组的沉默用户提单率仅 5.67%，实验组也只到 11.17%——对完全沉默的用户，30% 降息券的唤醒能力有限；券真正的价值在于把「已经在空窗期活跃、犹豫是否下单」的用户推向成交。

03

活跃率分组平衡，结论可信。

对照组活跃率 56.11% vs 实验组 55.53%，几乎一致，说明「活跃用户」不是券带来的，而是两组的既有特征——后续提单率差异可归因于券本身。

五、核心结论汇总

A

30% 降息券显著提升前三天提单率 +6.52pp。

实验组 19.64% vs 对照组 13.12%，三批次方向一致（+6.82 / +6.96 / +5.60pp）。

B

券对「第一阶段活跃用户」拉动最强（+7.47pp）。

活跃用户实验组 26.42% vs 对照 18.95%；沉默用户仅 +5.50pp。券的价值集中在高意向人群的「临门一脚」。

C

第 1 天（触达当天）是黄金窗口。

第 1 天实验组提单率 7.90% vs 对照 4.98%（+2.92pp），为三天内最大差距；券期内实验组全程保持高水位。

六、策略建议

A

把资源聚焦「第一阶段活跃用户」。

这类用户空窗期已主动回流，是转化确定性最高的人群（实验组提单率 26.42%）。建议对活跃用户加码券+人工触达，优先跟进。

B

触达当天做足动作，抓住第 1 天黄金窗口。

第 1 天差距最大（+2.92pp），应在触达当天完成首轮 push/短信/站内触达，避免错过券期前期的转化高峰。

C

对沉默用户不建议依赖降息券，考虑其他激励或降低优先级。

沉默用户实验组提单率仅 11.17%，券的唤醒能力有限，投入产出比偏低；可探索提额/免息/召回活动等组合手段，或减少对其的补贴投放。

附录：完整 PGSQL

以下代码覆盖本报告的用户构建、前三天提单率、活跃/沉默交叉与逐日提单，全部为「前三天提单 + 第一阶段活跃」口径。

模块一：构建 3 批召回用户 + 前三天提单率
-- 数据源：no_apply_0813_0818_30pct / 0815_0820 / 0816_0821
-- 召回日 = 表名最后一个日期（0813_0818 -> 2026-08-18）
-- 前三天 = 召回日、召回日+1、召回日+2（与 3 天券有效期一致）
-- 第一阶段活跃 = active_days_cnt > 0（结清后 ~ 触达前的 4 天空窗期内有活跃）
WITH u AS (
    SELECT churn_user_id::bigint AS user_id, ab_group, active_days_cnt, '2026-08-18'::date AS recall_date
    FROM wangchuanliang.no_apply_0813_0818_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, active_days_cnt, '2026-08-20'::date
    FROM wangchuanliang.no_apply_0815_0820_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, active_days_cnt, '2026-08-21'::date
    FROM wangchuanliang.no_apply_0816_0821_30pct
),
applied AS (
    SELECT DISTINCT o.user_id, o.apply_date
    FROM wangchuanliang.order_loan_f_v2_copy o
)
SELECT
    u.ab_group                                                             AS 分组,
    COUNT(DISTINCT u.user_id)                                              AS 用户数,
    COUNT(DISTINCT CASE WHEN u.active_days_cnt > 0 THEN u.user_id END)     AS 第一阶段活跃用户,
    COUNT(DISTINCT CASE WHEN a.user_id IS NOT NULL AND a.apply_date BETWEEN u.recall_date AND u.recall_date + 2
                         THEN u.user_id END)                               AS 前三天提单用户,
    COUNT(DISTINCT CASE WHEN u.active_days_cnt > 0 AND a.user_id IS NOT NULL
                          AND a.apply_date BETWEEN u.recall_date AND u.recall_date + 2
                         THEN u.user_id END)                               AS 活跃且前三天提单
FROM u
LEFT JOIN applied a ON a.user_id = u.user_id
GROUP BY u.ab_group
ORDER BY u.ab_group;
模块二：前三天逐日提单
-- 逐日提单 = 召回日当天 / 召回日+1 / 召回日+2
WITH u AS (
    SELECT churn_user_id::bigint AS user_id, ab_group, '2026-08-18'::date AS recall_date
    FROM wangchuanliang.no_apply_0813_0818_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, '2026-08-20'::date FROM wangchuanliang.no_apply_0815_0820_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, '2026-08-21'::date FROM wangchuanliang.no_apply_0816_0821_30pct
)
SELECT
    u.ab_group                                                             AS 分组,
    COUNT(DISTINCT CASE WHEN o.apply_date = u.recall_date THEN u.user_id END)       AS 第1天提单,
    COUNT(DISTINCT CASE WHEN o.apply_date = u.recall_date + 1 THEN u.user_id END)   AS 第2天提单,
    COUNT(DISTINCT CASE WHEN o.apply_date = u.recall_date + 2 THEN u.user_id END)   AS 第3天提单
FROM u
LEFT JOIN wangchuanliang.order_loan_f_v2_copy o
       ON o.user_id = u.user_id
      AND o.apply_date BETWEEN u.recall_date AND u.recall_date + 2
GROUP BY u.ab_group
ORDER BY u.ab_group;
模块三：第一阶段活跃 / 沉默 × 前三天提单
-- 活跃 = active_days_cnt > 0（空窗期有动作）；沉默 = active_days_cnt = 0
WITH u AS (
    SELECT churn_user_id::bigint AS user_id, ab_group, active_days_cnt, '2026-08-18'::date AS recall_date
    FROM wangchuanliang.no_apply_0813_0818_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, active_days_cnt, '2026-08-20'::date FROM wangchuanliang.no_apply_0815_0820_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, active_days_cnt, '2026-08-21'::date FROM wangchuanliang.no_apply_0816_0821_30pct
),
applied AS (
    SELECT DISTINCT o.user_id
    FROM wangchuanliang.order_loan_f_v2_copy o
)
SELECT
    u.ab_group                                                             AS 分组,
    CASE WHEN u.active_days_cnt > 0 THEN '活跃' ELSE '沉默' END             AS 分段,
    COUNT(*)                                                               AS 用户数,
    SUM(CASE WHEN a.user_id IS NOT NULL AND EXISTS (
                 SELECT 1 FROM wangchuanliang.order_loan_f_v2_copy o2
                 WHERE o2.user_id = u.user_id
                   AND o2.apply_date BETWEEN u.recall_date AND u.recall_date + 2
              ) THEN 1 ELSE 0 END)                                         AS 前三天提单
FROM u
LEFT JOIN applied a ON a.user_id = u.user_id
GROUP BY u.ab_group, CASE WHEN u.active_days_cnt > 0 THEN '活跃' ELSE '沉默' END
ORDER BY u.ab_group, 分段;
口径说明：3 批 T4 用户合并（召回日 08-18 / 08-20 / 08-21）。前三天 = 触达日 + 触达日+1 + 触达日+2（与 3 天券有效期一致）；第一阶段 = 上笔结清日至触达日前一天（4 天空窗期，如 0813_0818 批次为 08-14~08-17）；第一阶段活跃 = 空窗期内有活跃行为（active_days_cnt > 0）。提单以 order_loan_f_v2_copy.apply_date 判定。
本报告聚焦「前三天提单率」，不含盈利率/逾期率（观察期过短，尚未到期）。
